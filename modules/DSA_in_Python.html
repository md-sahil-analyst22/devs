📊 Topic 1 · Foundation
Big-O & Complexity
Big-O describes how an algorithm's running time or memory grows as the input grows. It's the language you use to compare two solutions before you ever run them — the single most important mental model in DSA.

Two things we measure

⏱️ Time complexity
How the number of operations scales with input size n. We care about the dominant term as n → ∞.
💾 Space complexity
How much extra memory an algorithm needs beyond the input. Recursion stacks and auxiliary arrays count here.

The complexity ladder

NotationNameExampleRating
O(1)ConstantDict lookup, array indexExcellent
O(log n)LogarithmicBinary searchGreat
O(n)LinearScan a list onceGood
O(n log n)LinearithmicMerge sort, TimsortFair
O(n²)QuadraticNested loops, bubble sortPoor
O(2ⁿ)ExponentialNaive recursive FibonacciBad
O(n!)FactorialGenerating all permutationsTerrible

How growth compares

Drop constants and lower-order terms. O(2n + 5) is just O(n), and O(n² + n) is O(n²). Big-O captures the shape of growth, not the exact operation count.
Best / average / worst. Big-O usually refers to the worst case. "Amortized" describes the average cost per operation over a sequence — e.g. Python's list.append is amortized O(1) even though occasional resizes cost O(n).
📦 Topic 2 · Foundation
Arrays & Python Lists
An array stores elements in one contiguous block of memory, so any element is reachable in O(1) by index. Python's built-in list is a dynamic array: it grows automatically and is the workhorse of everyday Python.

What & Why

🎯 Contiguous memory
Elements sit back-to-back. Address of element i = base + i × size, so indexing is instant and cache-friendly.
📈 Dynamic sizing
A Python list over-allocates spare slots. When it fills up it copies to a bigger block — making append amortized O(1).

Operation costs

OperationExampleComplexity
Index / updatea[i]O(1)
Appenda.append(x)O(1)*
Pop from enda.pop()O(1)
Insert / delete at fronta.insert(0,x)O(n)
Search (unsorted)x in aO(n)
Slicea[i:j]O(k)

* amortized — occasional resize is O(n)

In practice

arrays.py
nums = [3, 1, 4, 1, 5, 9]

nums[2]            # 4        → O(1) index
nums.append(2)     # add to end → O(1) amortized
nums.pop()         # remove last → O(1)
nums.insert(0, 0)  # shift everything right → O(n)

# List comprehension: build a new list in one pass
squares = [x * x for x in nums if x > 2]

# Two-pointer pattern: reverse in place, O(n) time / O(1) space
def reverse(a):
    lo, hi = 0, len(a) - 1
    while lo < hi:
        a[lo], a[hi] = a[hi], a[lo]
        lo += 1
        hi -= 1
    return a
Need fixed-type numeric arrays? Use array for compact typed storage, or NumPy for vectorised math. For O(1) inserts/removes at both ends, reach for collections.deque (next sections).
🔗 Topic 3 · Linear
Linked Lists
A linked list chains together nodes, where each node holds a value and a reference to the next node. There's no contiguous block — so inserting or deleting at a known position is O(1), but you lose O(1) random access.

Structure

Singly linked list in Python

linked_list.py
class Node:
    def __init__(self, val):
        self.val = val
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def push_front(self, val):        # O(1)
        node = Node(val)
        node.next = self.head
        self.head = node

    def traverse(self):               # O(n)
        cur = self.head
        while cur:
            print(cur.val)
            cur = cur.next

    def reverse(self):                # O(n), classic interview question
        prev, cur = None, self.head
        while cur:
            cur.next, prev, cur = prev, cur, cur.next
        self.head = prev

Linked list vs array

Linked list wins

  • O(1) insert / delete at a known node
  • Grows without copying / resizing
  • Great for queues, LRU caches, adjacency lists

Linked list loses

  • No O(1) random access — must walk from head
  • Extra memory per node (the pointer)
  • Poor cache locality vs contiguous arrays
📚 Topic 4 · Linear
Stacks — LIFO
A stack is Last-In, First-Out: the last item pushed is the first popped, like a stack of plates. In Python a plain list is a stack — append to push, pop to pop, both O(1).

How it works

stack.py
stack = []
stack.append(10)     # push → O(1)
stack.append(20)
top = stack[-1]      # peek → O(1)   (20)
stack.pop()          # pop  → O(1)   (removes 20)

# Classic use: check balanced brackets
def is_balanced(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

is_balanced("({[]})")   # True
is_balanced("(]")       # False
Where stacks show up: undo/redo, browser back button, the function call stack, expression evaluation, and iterative DFS (depth-first search).
🎟️ Topic 5 · Linear
Queues & Deques — FIFO
A queue is First-In, First-Out: items leave in the order they arrived, like a line at a counter. Use collections.deque — it gives O(1) push/pop at both ends, unlike a list where pop(0) is O(n).

How it works

queue.py
from collections import deque

q = deque()
q.append(10)        # enqueue (back)  → O(1)
q.append(20)
front = q.popleft() # dequeue (front) → O(1)   (10)

# deque works as a stack too, and as a double-ended queue
dq = deque([2, 3])
dq.appendleft(1)    # → deque([1, 2, 3])
dq.pop()            # remove from back → O(1)
StructureFront opsBack opsBest for
listO(n)O(1)Stack
dequeO(1)O(1)Queue / stack / sliding window
queue.QueueO(1)O(1)Thread-safe producer/consumer
Queues power BFS. Breadth-first search of a graph or tree processes nodes level by level using a FIFO queue — you'll see it in the Graphs section.
🔑 Topic 6 · Linear
Hash Tables — dict & set
A hash table maps keys to values by running each key through a hash function to pick a storage bucket, giving average O(1) lookup, insert, and delete. Python's dict and set are hash tables — arguably the most useful structures in the language.

How hashing works

hashing.py
prices = {"apple": 5, "banana": 3}
prices["apple"]        # O(1) lookup
prices["cherry"] = 8   # O(1) insert
"banana" in prices     # O(1) membership test

seen = set()           # a set = keys only, no values
seen.add(4)
4 in seen              # O(1)

# Killer pattern: count things in one pass, O(n)
from collections import Counter
freq = Counter("mississippi")   # {'i':4,'s':4,'p':2,'m':1}

# Two-sum: find a pair adding to target in O(n) using a dict
def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
Average O(1), worst O(n). If many keys collide into the same bucket, operations degrade toward linear. Good hash functions and resizing keep this rare. Keys must be hashable (immutable) — strings, numbers, and tuples work; lists don't.
🌳 Topic 7 · Hierarchical
Trees & Binary Search Trees
A tree is a hierarchy of nodes with one root and no cycles. A Binary Search Tree (BST) keeps things ordered: every left child is smaller than its parent, every right child larger — so search, insert, and delete run in O(log n) when the tree stays balanced.

Anatomy of a BST

bst.py
class TreeNode:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None

def insert(root, val):                # O(h) — h = height
    if root is None:
        return TreeNode(val)
    if val < root.val:
        root.left = insert(root.left, val)
    else:
        root.right = insert(root.right, val)
    return root

def search(root, val):                # O(h)
    while root and root.val != val:
        root = root.left if val < root.val else root.right
    return root

def inorder(root):                    # visits nodes in sorted order
    if root:
        inorder(root.left)
        print(root.val)
        inorder(root.right)

Traversals

TraversalOrderCommon use
InorderLeft · Node · RightSorted output from a BST
PreorderNode · Left · RightCopy / serialize a tree
PostorderLeft · Right · NodeDelete / free a tree, evaluate expressions
Level-orderBreadth-first (queue)Shortest path by depth
Balance matters. A BST is O(log n) only when balanced. Insert already-sorted data and it degenerates into a linked list — O(n). Self-balancing variants (AVL, Red-Black trees) guarantee O(log n); Python's sortedcontainers library provides these in practice.
⛰️ Topic 8 · Hierarchical
Heaps & Priority Queues
A heap is a complete binary tree where every parent is smaller (min-heap) or larger (max-heap) than its children. That single rule gives you the smallest/largest element in O(1) and insert/remove in O(log n) — the basis of a priority queue.

Tree view & array view

heap.py
import heapq

h = []
heapq.heappush(h, 5)      # O(log n)
heapq.heappush(h, 1)
heapq.heappush(h, 3)
heapq.heappop(h)          # 1  → always the smallest, O(log n)
h[0]                      # peek min → O(1)

# Turn a list into a heap in place → O(n)
nums = [5, 1, 8, 3, 2]
heapq.heapify(nums)

# k largest / smallest → O(n log k)
heapq.nlargest(2, nums)   # [8, 5]

# Max-heap trick: push negatives
maxh = []
heapq.heappush(maxh, -5)
-heapq.heappop(maxh)      # 5
When to reach for a heap: "top-k" problems, merging k sorted lists, Dijkstra's shortest path, task scheduling by priority, and running medians. Any time you repeatedly need the current min/max, a heap beats re-sorting.
🕸️ Topic 9 · Graphs
Graphs — BFS & DFS
A graph is a set of vertices connected by edges — think maps, social networks, or web links. The two fundamental traversals are BFS (breadth-first, uses a queue) and DFS (depth-first, uses recursion or a stack).

Representing a graph

📇 Adjacency list
A dict mapping each node to its neighbours. Space O(V+E). Best for sparse graphs — the usual choice.
🔲 Adjacency matrix
A V×V grid of 0/1. O(1) edge lookup but O(V²) space. Best for dense graphs.
graph.py
from collections import deque

graph = {
    'A': ['B', 'C'],
    'B': ['A', 'C', 'D'],
    'C': ['A', 'B', 'D'],
    'D': ['B', 'C'],
}

def bfs(start):                       # level by level, uses a queue
    visited = {start}
    q = deque([start])
    while q:
        node = q.popleft()
        print(node)
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)
                q.append(nb)

def dfs(node, visited=None):          # go deep first, uses recursion
    if visited is None:
        visited = set()
    visited.add(node)
    print(node)
    for nb in graph[node]:
        if nb not in visited:
            dfs(nb, visited)

Sorting Algorithms
Sorting arranges data in order and unlocks faster searching and grouping. You rarely write your own in production — Python's sorted() uses Timsort — but understanding the trade-offs is core interview material.

The landscape

AlgorithmBestAverageWorstSpaceStable

InsertionO(n)O(n²)O(n²)O(1)Yes

Two must-know sorts

sorting.py
def merge_sort(a):                    # stable, guaranteed O(n log n)
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    merged, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            merged.append(left[i]); i += 1
        else:
            merged.append(right[j]); j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged

def quick_sort(a):                    # fast in practice, O(n log n) avg
    if len(a) <= 1:
        return a
    pivot = a[len(a) // 2]
    less = [x for x in a if x < pivot]
    equal = [x for x in a if x == pivot]
    greater = [x for x in a if x > pivot]
    return quick_sort(less) + equal + quick_sort(greater)
In real code, just use the built-ins. sorted(data) returns a new sorted list; data.sort() sorts in place. Sort by a key with sorted(users, key=lambda u: u.age). Both are Timsort — stable and adaptive to partially-sorted input.
🎯 Topic 11 · Algorithms
Binary Search
Binary search finds a target in a sorted array by repeatedly halving the search range — O(log n) instead of O(n). A million elements take at most 20 comparisons. The catch: the data must already be sorted.

Halving the range

binary_search.py
def binary_search(a, target):         # O(log n), a must be sorted
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        elif a[mid] < target:
            lo = mid + 1              # target is in the right half
        else:
            hi = mid - 1             # target is in the left half
    return -1                        # not found

# The standard library already has it:
import bisect
a = [1, 3, 5, 7, 9]
bisect.bisect_left(a, 5)   # 2  → leftmost insert position
bisect.insort(a, 4)        # keep the list sorted while inserting
Common pitfalls: the array must be sorted first; use lo <= hi (not <) so a single-element range is checked; and always move lo/hi past mid to avoid infinite loops.
🌀 Topic 12 · Algorithms
Recursion
A recursive function solves a problem by calling itself on a smaller version of the same problem. Every recursion needs a base case (when to stop) and a recursive case (how to shrink the problem toward that base).

The two ingredients

🛑 Base case
The simplest input, answered directly with no further calls. Without it, recursion never stops — you hit a RecursionError.
🔁 Recursive case
Break the problem into smaller pieces, call yourself on them, and combine the results. Each call must move toward the base case.

Recursion tree — fib(4)

recursion.py
def factorial(n):                     # 5! = 5 * 4 * 3 * 2 * 1
    if n <= 1:                        # base case
        return 1
    return n * factorial(n - 1)      # recursive case

def fib(n):                           # naive: O(2ⁿ) — recomputes subtrees
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

from functools import lru_cache
@lru_cache(maxsize=None)              # cache results → drops to O(n)
def fib_fast(n):
    if n < 2:
        return n
    return fib_fast(n - 1) + fib_fast(n - 2)
Mind the stack. Each call adds a frame to the call stack; Python caps recursion depth near 1000 by default. Deep recursion may need an iterative rewrite. The naive fib above is the poster child for why Dynamic Programming exists — up next.
🧩 Topic 13 · Algorithms
Dynamic Programming
Dynamic Programming (DP) speeds up recursion by storing answers to subproblems so each is solved once. It applies when a problem has overlapping subproblems and optimal substructure — turning exponential solutions into polynomial ones.

When DP applies

♻️ Overlapping subproblems
The same smaller problem is solved many times (like fib(2) appearing all over the recursion tree). Cache it once.
🏗️ Optimal substructure
The best answer is built from best answers to subproblems — so combining sub-solutions gives the global optimum.

Two styles

ApproachDirectionHow
MemoizationTop-downNormal recursion + a cache (@lru_cache)
TabulationBottom-upFill a table iteratively from base cases
dp.py
# Tabulation: Fibonacci bottom-up, O(n) time / O(1) space
def fib(n):
    if n < 2:
        return n
    prev, cur = 0, 1
    for _ in range(2, n + 1):
        prev, cur = cur, prev + cur
    return cur

# Climbing stairs: how many ways to climb n steps taking 1 or 2 at a time?
def climb(n):
    dp = [0] * (n + 1)
    dp[0] = dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]   # reuse solved subproblems
    return dp[n]

# 0/1 Knapsack: max value within a weight capacity
def knapsack(weights, values, cap):
    dp = [0] * (cap + 1)
    for w, v in zip(weights, values):
        for c in range(cap, w - 1, -1):
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp[cap]
The DP recipe: (1) define the subproblem in words, (2) write the recurrence relating it to smaller subproblems, (3) identify base cases, (4) decide memoization vs tabulation, (5) read the answer off the table. Classic problems: coin change, longest common subsequence, edit distance, grid paths.

Problem-solving checklist

  • Clarify — inputs, outputs, constraints, and edge cases (empty, single element, duplicates).
  • Brute force first — get any correct solution, then state its complexity.
  • Spot the bottleneck — which step is slow, and which structure removes it?
  • Trade space for time — a hash map or cache often turns O(n²) into O(n).
  • Test — walk through your example by hand before claiming it works.
Practice beats reading. Pick one pattern, solve 3–4 problems with it until it's second nature, then move on. Depth per pattern matters more than breadth.
