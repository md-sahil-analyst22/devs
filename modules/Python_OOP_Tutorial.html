📚 1. Introduction to OOP

Video Chapter: 0:00 - Introduction to OOP

What is Object-Oriented Programming?

Object-Oriented Programming (OOP) is a way of writing code that organizes software around data (objects) instead of just functions and logic. Think of it like this: instead of writing a long list of instructions, you create "things" that have both data (what they know) and methods (what they can do).

💡 Real-World Analogy

Think of a Car as an object. A car has:

  • Attributes (Data): color, brand, model, speed, fuel_level
  • Methods (Behavior): accelerate(), brake(), honk(), refuel()

🎯 2. Classes & Objects

Video Chapters: 2:42 - Concept | 3:45 - Example | 8:55 - Code Implementation

What is a Class?

A class is a blueprint or template for creating objects. It defines what attributes (data) and methods (behavior) the objects will have. Think of a class as a cookie cutter, and objects as the actual cookies.

What is an Object?

An object is an instance of a class. When a class is defined, no memory is used until you create an object from it. Each object has its own unique data but shares the same methods from the class.

💡 Key Point for Beginners

A class is like a recipe, and an object is the dish you make using that recipe. You can make many dishes from one recipe, each with different ingredients (attributes) but following the same instructions (methods).

Creating Your First Class in Python

In Python, we use the class keyword to define a class:

Python — Basic Class Definition 
# Defining a simple class
class Dog:
    # Class attribute (shared by ALL instances)
    species = "Canis familiaris"

    # Constructor — called when object is created
    def __init__(self, name, age):
        # Instance attributes (unique to each object)
        self.name = name
        self.age = age

    # Instance method
    def bark(self):
        return f"{self.name} says: Woof! Woof!"

    # Another instance method
    def get_info(self):
        return f"{self.name} is {self.age} years old"

# Creating objects (instances) of the Dog class
dog1 = Dog("Buddy", 3)
dog2 = Dog("Max", 5)

# Accessing attributes
print(dog1.name)      # Output: Buddy
print(dog2.age)       # Output: 5
print(dog1.species)   # Output: Canis familiaris

# Calling methods
print(dog1.bark())       # Output: Buddy says: Woof! Woof!
print(dog2.get_info())   # Output: Max is 5 years old
Output
Buddy
5
Canis familiaris
Buddy says: Woof! Woof!
Max is 5 years old

Understanding self — The Most Confusing Part for Beginners

The self parameter is a reference to the current instance of the class. It allows us to access the attributes and methods of the object. When you call dog1.bark(), Python automatically passes dog1 as self.

⚠️ Important Rule

The self parameter must be the first parameter of any instance method. You don't pass it explicitly when calling the method — Python handles it automatically behind the scenes.

The __init__ Method (Constructor)

The __init__ method is a special method called automatically when a new object is created. It's used to set up the object's initial attributes. This is also known as the constructor.

Python — Constructor Deep Dive 
class Student:
    # Class attribute — same for ALL students
    school_name = "Python High School"

    def __init__(self, name, grade, student_id):
        # Instance attributes — unique for EACH student
        self.name = name
        self.grade = grade
        self.student_id = student_id
        self.subjects = []  # Can have default values

    def enroll_subject(self, subject):
        self.subjects.append(subject)
        return f"{subject} enrolled successfully!"

    def get_report(self):
        return f"""
        Student Report
        ==============
        Name: {self.name}
        ID: {self.student_id}
        Grade: {self.grade}
        School: {self.school_name}
        Subjects: {', '.join(self.subjects)}
        """

# Creating student objects
student1 = Student("Alice", "10th", "S001")
student2 = Student("Bob", "11th", "S002")

# Each student has unique data
student1.enroll_subject("Math")
student1.enroll_subject("Science")
student2.enroll_subject("History")

print(student1.get_report())

Class Attribute vs Instance Attribute

This is a common source of confusion. Here's the clear difference:

Feature Class Attribute Instance Attribute
Where defined? Inside class, outside methods Inside __init__ using self
Shared? Shared across ALL instances Unique to EACH instance
How to access? ClassName.attr or obj.attr Only via obj.attr
Memory One copy for all objects Separate copy per object
Use Case Constants, default values Object-specific data

Real-World Example: Bank Account

Python — Bank Account Class 
class BankAccount:
    # Class attribute — interest rate for ALL accounts
    interest_rate = 0.05  # 5% interest

    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance
        self.transaction_history = []

    def deposit(self, amount):
        if amount > 0:
            self.balance += amount
            self.transaction_history.append(f"Deposited: ${amount}")
            return f"Deposit successful! New balance: ${self.balance}"
        return "Invalid deposit amount!"

    def withdraw(self, amount):
        if 0 < amount <= self.balance:
            self.balance -= amount
            self.transaction_history.append(f"Withdrawn: ${amount}")
            return f"Withdrawal successful! Remaining: ${self.balance}"
        return "Insufficient funds or invalid amount!"

    def get_balance(self):
        return f"Current balance: ${self.balance}"

    def apply_interest(self):
        interest = self.balance * BankAccount.interest_rate
        self.balance += interest
        return f"Interest applied! New balance: ${self.balance}"

# Creating bank accounts
account1 = BankAccount("John Doe", 1000)
account2 = BankAccount("Jane Smith", 500)

# Performing transactions
print(account1.deposit(500))
print(account1.withdraw(200))
print(account1.get_balance())
print(account1.apply_interest())
Output
Deposit successful! New balance: $1500
Withdrawal successful! Remaining: $1300
Current balance: $1300
Interest applied! New balance: $1365.0

Special Methods (Dunder Methods)

Python provides special methods that start and end with double underscores (__). These let you define how objects behave with built-in operations:

Python — Special Methods 
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    # String representation — used by print() and str()
    def __str__(self):
        return f"Vector({self.x}, {self.y})"

    # Official representation — used by repr()
    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    # Addition operator (+)
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    # Equality operator (==)
    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    # Length of vector
    def __len__(self):
        return int((self.x ** 2 + self.y ** 2) ** 0.5)

v1 = Vector(2, 3)
v2 = Vector(4, 5)

print(v1)           # Vector(2, 3) — uses __str__
v3 = v1 + v2        # Uses __add__
print(v3)           # Vector(6, 8)
print(v1 == v2)     # False — uses __eq__
print(len(v3))    # 10 — uses __len__

👨‍👧 4. Inheritance

Video Chapters: 39:07 - Concept | 41:26 - Code Implementation

What is Inheritance?

Inheritance is when a new class (child/subclass) gets properties and methods from an existing class (parent/superclass). It promotes code reusability and creates a natural hierarchy between classes.

💡 Real-World Analogy

A child inherits traits from their parents (eye color, height). Similarly, in OOP, a child class inherits attributes and methods from its parent class. The child can also have its own unique traits (new attributes/methods) or modify inherited ones.

Single Inheritance Example

Python — Single Inheritance 
# Parent Class
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        return f"{self.name} is eating"

    def sleep(self):
        return f"{self.name} is sleeping"

    def make_sound(self):
        return "Some generic animal sound"

# Child Class — inherits from Animal
class Dog(Animal):
    def __init__(self, name, age, breed):
        # Call parent constructor using super()
        super().__init__(name, age)
        self.breed = breed

    # Override parent method
    def make_sound(self):
        return f"{self.name} says: Woof! Woof!"

    # New method specific to Dog
    def fetch(self):
        return f"{self.name} is fetching the ball!"

# Another Child Class
class Cat(Animal):
    def __init__(self, name, age, color):
        super().__init__(name, age)
        self.color = color

    def make_sound(self):
        return f"{self.name} says: Meow!"

    def climb(self):
        return f"{self.name} is climbing the tree!"

# Using the classes
dog = Dog("Buddy", 3, "Golden Retriever")
cat = Cat("Whiskers", 2, "Orange")

print(dog.eat())          # Inherited from Animal
print(dog.make_sound())   # Overridden in Dog
print(dog.fetch())        # Unique to Dog
print(cat.sleep())        # Inherited from Animal
print(cat.make_sound())   # Overridden in Cat
Output
Buddy is eating
Buddy says: Woof! Woof!
Buddy is fetching the ball!
Whiskers is sleeping
Whiskers says: Meow!

Python — Multiple Inheritance 
# Parent Class 1
class Flying:
    def fly(self):

class Swimming:

Multilevel Inheritance

Python — Multilevel Inheritance 
# Grandparent Class
class Vehicle:
    def __init__(self, brand):
        self.brand = brand

    def start(self):
        return f"{self.brand} vehicle starting..."

    def stop(self):
        return f"{self.brand} vehicle stopping..."

# Parent Class (inherits from Vehicle)
class Car(Vehicle):
    def __init__(self, brand, model):
        super().__init__(brand)
        self.model = model
        self.wheels = 4

    def honk(self):
        return "Beep! Beep!"

    def drift(self):
        return f"{self.model} is drifting!"

# Child Class (inherits from Car)
class ElectricCar(Car):
    def __init__(self, brand, model, battery_capacity):
        super().__init__(brand, model)
        self.battery_capacity = battery_capacity
        self.charge_level = 100

    def charge(self):
        self.charge_level = 100
        return f"{self.model} is fully charged!"

    def drive_eco(self):
        return f"{self.model} driving in eco mode ⚡"

# ElectricCar has access to ALL methods!
tesla = ElectricCar("Tesla", "Model S", "100 kWh")

print(tesla.start())        # From Vehicle
print(tesla.honk())         # From Car
print(tesla.charge())       # From ElectricCar
print(tesla.drive_eco())    # From ElectricCar
print(f"Battery: {tesla.battery_capacity}")
print(f"Wheels: {tesla.wheels}")
Output
Tesla vehicle starting...
Beep! Beep!
Model S is fully charged!
Model S driving in eco mode ⚡
Battery: 100 kWh
Wheels: 4
💡 The super() Function

The super() function calls the parent class method. It's commonly used in the child's __init__ to initialize inherited attributes. This avoids duplicating code and makes maintenance easier.

Method Resolution Order (MRO)

When using multiple inheritance, Python follows the Method Resolution Order (MRO) to determine which method to call. You can check the MRO using the __mro__ attribute:

Python — Checking MRO 
print(ElectricCar.__mro__)
# Output: (<class 'ElectricCar'>, <class 'Car'>, <class 'Vehicle'>, <class 'object'>)

# Or use the mro() method
print(ElectricCar.mro())
⚠️ The Diamond Problem

In multiple inheritance, if two parent classes inherit from the same grandparent, Python's MRO ensures each class is called only once. Python uses the C3 Linearization algorithm to resolve this.

🎭 5. Polymorphism

Video Chapters: 50:20 - Concept | 52:04 - Code Implementation

What is Polymorphism?

Polymorphism means "many forms." In OOP, it allows objects of different classes to be treated as objects of a common parent class. The same method call can behave differently based on the object's actual class.

💡 Real-World Analogy

Consider a + operator: with numbers it adds (5 + 3 = 8), with strings it concatenates ("Hello" + " World" = "Hello World"). The same operator behaves differently based on the operands — that's polymorphism!

🎭 Polymorphism in Action
    Same Message → Different Behaviors

    for animal in [dog, cat, bird]:
        animal.make_sound()

    dog.make_sound()  ──►  "Woof! Woof!"
    cat.make_sound()  ──►  "Meow!"
    bird.make_sound() ──►  "Chirp! Chirp!"

    Same method name, different implementations!

Polymorphism with Inheritance (Method Overriding)

Python — Polymorphism with Method Overriding 
class Animal:
    def __init__(self, name):

    # Base method — will be overridden by children
    def make_sound(self):
        return "Some sound"

    def move(self):
        return f"{self.name} is moving"

class Dog(Animal):

Polymorphism with Functions (Duck Typing)

Python — Polymorphic Functions & Duck Typing 
# Python is dynamically typed — polymorphism comes naturally
def add(a, b):
    return a + b

# Works with integers
print(add(5, 3))           # 8

# Works with strings
print(add("Hello, ", "World!"))  # Hello, World!

# Works with lists
print(add([1, 2], [3, 4]))    # [1, 2, 3, 4]

# Polymorphic behavior with objects
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def __str__(self):
        return f"Rectangle({self.width}x{self.height})"

class Circle:
    def __init__(self, radius):
        self.radius = radius
        self.pi = 3.14159

    def area(self):
        return self.pi * self.radius ** 2

    def __str__(self):
        return f"Circle(r={self.radius})"

class Triangle:
    def __init__(self, base, height):
        self.base = base
        self.height = height

    def area(self):
        return 0.5 * self.base * self.height

    def __str__(self):
        return f"Triangle(b={self.base}, h={self.height})"

# Polymorphic function — works with ANY shape!
def print_area(shape):
    print(f"{shape} has area: {shape.area():.2f}")

# Create different shapes
shapes = [
    Rectangle(5, 3),
    Circle(4),
    Triangle(6, 4)
]

# Same function, different calculations!
for shape in shapes:
    print_area(shape)
Output
Rectangle(5x3) has area: 15.00
Circle(r=4) has area: 50.27
Triangle(b=6, h=4) has area: 12.00

Duck Typing in Python

Python follows the principle: "If it looks like a duck and quacks like a duck, it is a duck." This means Python doesn't check the type of object; it only checks if the required method exists.

Python — Duck Typing 
# No inheritance needed — just need the same method!
class Dog:
    def speak(self):
        return "Woof!"

class Cat:
    def speak(self):
        return "Meow!"

class Duck:
    def speak(self):
        return "Quack!"

class Robot:
    def speak(self):
        return "Beep boop!"

# This function doesn't care about the type!
def make_it_speak(thing):
    print(thing.speak())

# All these work — they all have a speak() method!
make_it_speak(Dog())
make_it_speak(Cat())
make_it_speak(Duck())
make_it_speak(Robot())

# This is Python's duck typing — no common parent needed!
💡 Types of Polymorphism
  • Method Overriding: Child class redefines parent's method
  • Method Overloading: Same method name, different parameters (not natively supported in Python, but achievable with default args)
  • Operator Overloading: Using operators with custom objects (via dunder methods like __add__)
  • Duck Typing: Python's dynamic typing approach — "if it walks like a duck..."

🔐 6. Encapsulation

Video Chapters: 53:34 - Concept | 55:07 - Code Implementation

What is Encapsulation?

Encapsulation is the bundling of data (attributes) and methods (functions) that operate on that data within a single unit (class). It restricts direct access to some of the object's components, which prevents accidental modification of data.

💡 Real-World Analogy

Consider a capsule medicine — the medicine is encapsulated inside a shell that protects it and controls how it's released. Similarly, in OOP, we encapsulate (protect) data inside a class and control access through methods.

Access Modifiers in Python

Python uses naming conventions to indicate access levels. Unlike Java, these are not strictly enforced — they are conventions that programmers follow:

Type Syntax Access Description
Public self.name Anywhere Accessible from anywhere — no restrictions
Protected self._name Class & Subclass Convention: "internal use only" — one underscore
Private self.__name Only inside class Name mangling prevents accidental access — two underscores

Public, Protected & Private Members

Python — Access Modifiers 
class Employee:
    def __init__(self, name, salary, ssn):
        self.name = name           # Public — accessible anywhere
        self._department = "IT"  # Protected — convention, use in subclass
        self.__ssn = ssn           # Private — only inside this class
        self.__salary = salary     # Private — name mangling applied

    # Getter method for private attribute
    def get_salary(self):
        return f"Salary: ${self.__salary}"

    # Setter method with validation
    def set_salary(self, new_salary):
        if new_salary > 0:
            self.__salary = new_salary
            return "Salary updated successfully!"
        return "Invalid salary amount!"

    # Getter for SSN (masked for security)
    def get_ssn(self):
        return f"XXX-XX-{self.__ssn[-4:]}"

    # Public method
    def display_info(self):
        return f"Name: {self.name}, Dept: {self._department}"

# Creating employee
emp = Employee("John Doe", 50000, "123-45-6789")

# Accessing public member
print(emp.name)              # ✅ Works: John Doe

# Accessing protected member (not recommended, but possible)
print(emp._department)       # ⚠️ Works but discouraged: IT

# Accessing private member directly
# print(emp.__salary)        # ❌ Error! Attribute doesn't exist

# Access via getter/setter (proper way)
print(emp.get_salary())      # ✅ Salary: $50000
print(emp.set_salary(60000)) # ✅ Salary updated!
print(emp.get_ssn())         # ✅ XXX-XX-6789 (masked)

# Name mangling — can access but shouldn't!
print(emp._Employee__ssn)    # ⚠️ Works but bad practice!
⚠️ Important Note for Beginners

Python doesn't enforce true privacy like Java or C++. The double underscore triggers name mangling (e.g., __salary becomes _Employee__salary), which makes it harder to accidentally access private members. However, a determined developer can still access them. Python follows the philosophy: "We're all consenting adults here."

Complete Encapsulation Example: Secure Bank Account

Python — Fully Encapsulated Bank Account 
class SecureBankAccount:
    # Class-level private attribute
    __bank_name = "Secure Bank Ltd."

    def __init__(self, owner, initial_balance=0):
        self.owner = owner                    # Public
        self._account_type = "Savings"        # Protected
        self.__balance = initial_balance      # Private
        self.__pin = "0000"                  # Private
        self.__transaction_log = []           # Private

    # ============ GETTERS ============
    def get_balance(self, pin):
        if self.__verify_pin(pin):
            return f"Balance: ${self.__balance}"
        return "Invalid PIN!"

    def get_transaction_history(self, pin):
        if self.__verify_pin(pin):
            return self.__transaction_log
        return "Access Denied!"

    # ============ SETTERS ============
    def set_pin(self, old_pin, new_pin):
        if self.__verify_pin(old_pin):
            if len(new_pin) == 4 and new_pin.isdigit():
                self.__pin = new_pin
                return "PIN changed successfully!"
            return "PIN must be 4 digits!"
        return "Invalid old PIN!"

    # ============ BUSINESS LOGIC ============
    def deposit(self, amount, pin):
        if not self.__verify_pin(pin):
            return "Invalid PIN!"
        if amount <= 0:
            return "Invalid amount!"

        self.__balance += amount
        self.__log_transaction(f"DEPOSIT: +${amount}")
        return f"Deposited ${amount}. New balance: ${self.__balance}"

    def withdraw(self, amount, pin):
        if not self.__verify_pin(pin):
            return "Invalid PIN!"
        if amount <= 0 or amount > self.__balance:
            return "Invalid amount or insufficient funds!"

        self.__balance -= amount
        self.__log_transaction(f"WITHDRAWAL: -${amount}")
        return f"Withdrawn ${amount}. Remaining: ${self.__balance}"

    # ============ PRIVATE METHODS ============
    def __verify_pin(self, pin):
        return pin == self.__pin

    def __log_transaction(self, transaction):
        from datetime import datetime
        timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        self.__transaction_log.append(f"[{timestamp}] {transaction}")

# Perform transactions

print(account.withdraw(200, "1234"))
print(account.get_balance("1234"))

# Attempt unauthorized access

The @property Decorator — Pythonic Getters & Setters

Python provides the @property decorator to create methods that can be accessed like attributes. This is the Pythonic way to implement encapsulation:

Python — Using @property 
class Temperature:
    def __init__(self, celsius=0):
        self.__celsius = celsius

    # Getter — access like: temp.celsius
    @property
    def celsius(self):
        return self.__celsius

    # Setter — set like: temp.celsius = 25
    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("Below absolute zero!")
        self.__celsius = value

    # Computed property — Fahrenheit
    @property
    def fahrenheit(self):
        return (self.__celsius * 9/5) + 32

    @fahrenheit.setter
    def fahrenheit(self, value):
        self.__celsius = (value - 32) * 5/9

temp = Temperature(25)
print(temp.celsius)      # Access like attribute: 25
temp.celsius = 30        # Set like attribute
print(temp.fahrenheit)   # Computed: 86.0
temp.fahrenheit = 100    # Convert and set
print(temp.celsius)      # 37.78
💡 Benefits of Encapsulation
  • Data Hiding: Internal state is protected from external modification
  • Validation: Control what values can be set through setters
  • Flexibility: Internal implementation can change without affecting external code
  • Security: Sensitive data is protected from unauthorized access

Video Chapters: 1:04:01 - Concept | 1:04:40 - Visual Explanation | 1:08:15 - Code Implementation

What is Abstraction?

Abstraction is the concept of hiding complex implementation details and showing only the essential features of an object. It helps reduce programming complexity by allowing you to focus on what an object does rather than how it does it.

💡 Real-World Analogy

When you drive a car, you use the steering wheel, accelerator, and brake — these are the abstract interface. You don't need to understand the complex internal mechanics of the engine, transmission, or braking system. The complex details are abstracted away from you.

Abstraction vs Encapsulation — What's the Difference?

🔐 Encapsulation

  • 📦 Bundles data and methods together
  • 🔒 Hides data (private variables)
  • 🎯 Protects information
  • 💡 Focus: "How to protect"
  • Example: Private variables, getters/setters

🎨 Abstraction

  • 🎭 Hides implementation details
  • 👁️ Shows only essential features
  • 🎯 Reduces complexity
  • 💡 Focus: "What to show"
  • Example: Abstract classes, interfaces

Abstract Classes in Python

Python uses the abc module (Abstract Base Classes) to create abstract classes. An abstract class:

  • Cannot be instantiated directly — you can't create objects from it
  • Can have abstract methods (must be implemented by children)
  • Can have concrete methods (implemented, inherited by children)
Python — Abstract Base Class 
from abc import ABC, abstractmethod

class Shape(ABC):  # Inherit from ABC

    # Abstract method — MUST be implemented by all subclasses
    @abstractmethod
    def area(self):
        pass

    # Another abstract method
    @abstractmethod
    def perimeter(self):
        pass

    # Concrete method — can be used by all subclasses
    def describe(self):
        return f"I am a {self.__class__.__name__}"

    def print_details(self):
        print(f"{self.describe()}")
        print(f"Area: {self.area()}")
        print(f"Perimeter: {self.perimeter()}")

# Concrete implementations
class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    # Must implement abstract method!
    def area(self):
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2

    def perimeter(self):
        return 2 * 3.14159 * self.radius

class Triangle(Shape):
    def __init__(self, a, b, c):
        self.a = a
        self.b = b
        self.c = c

    def area(self):
        # Heron's formula
        s = (self.a + self.b + self.c) / 2
        return (s * (s-self.a) * (s-self.b) * (s-self.c)) ** 0.5

    def perimeter(self):
        return self.a + self.b + self.c

from abc import ABC, abstractmethod
from datetime import datetime

class Payment(ABC):
    """Abstract base class for all payment methods"""

    def __init__(self, amount, currency="USD"):
        self._amount = amount
        self._currency = currency
        self._timestamp = None
        self._status = "PENDING"
        self._transaction_id = None

    # ============ ABSTRACT METHODS (must implement) ============
    @abstractmethod
    def validate(self):
        """Validate payment details"""
        pass

    @abstractmethod
    def process_payment(self):
        """Process the actual payment"""
        pass

    @abstractmethod
    def generate_receipt(self):
        """Generate payment receipt"""
        pass

    # ============ CONCRETE METHODS (shared logic) ============
    def execute(self):
        """Template method — defines the payment workflow"""
        print(f"
💳 Processing ${self._amount} {self._currency} payment...")

        try:
            # Step 1: Validate
            if not self.validate():
                self._status = "FAILED"
                return "❌ Validation failed!"

            # Step 2: Process
            result = self.process_payment()
            self._timestamp = datetime.now()
            self._status = "SUCCESS"
            self._transaction_id = self._generate_transaction_id()

            # Step 3: Generate Receipt
            receipt = self.generate_receipt()

            print(f"✅ Payment successful!")
            print(f"📄 Transaction ID: {self._transaction_id}")
            return receipt

        except Exception as e:
            self._status = "ERROR"
            return f"❌ Error: {str(e)}"

    def get_status(self):
        return self._status

    def _generate_transaction_id(self):
        return f"TXN{datetime.now().strftime('%Y%m%d%H%M%S')}"

Interface-like Behavior in Python

In Python, we can create interface-like behavior using abstract classes with all abstract methods:

Python — Interface Pattern 
from abc import ABC, abstractmethod

class DatabaseInterface(ABC):
    """Interface for database operations — all methods are abstract"""

    @abstractmethod
    def connect(self):
        pass

    @abstractmethod
    def disconnect(self):
        pass

    @abstractmethod
    def execute_query(self, query):
        pass

    @abstractmethod
    def fetch_all(self):
        pass

class MySQLDatabase(DatabaseInterface):
    def connect(self):
        return "Connected to MySQL"

    def disconnect(self):
        return "Disconnected from MySQL"

    def execute_query(self, query):
        return f"MySQL executing: {query}"

    def fetch_all(self):
        return ["MySQL Row 1", "MySQL Row 2"]

class PostgreSQLDatabase(DatabaseInterface):
    def connect(self):
        return "Connected to PostgreSQL"

    def disconnect(self):
        return "Disconnected from PostgreSQL"

    def execute_query(self, query):
        return f"PostgreSQL executing: {query}"

    def fetch_all(self):
        return ["PG Row 1", "PG Row 2"]

# Can swap databases without changing application code!
def run_application(db: DatabaseInterface):
    print(db.connect())
    print(db.execute_query("SELECT * FROM users"))
    print(db.fetch_all())
    print(db.disconnect())

print("=== MySQL ===")
