Module 1 · Introduction

What is FastAPI?

FastAPI is a modern, high-performance Python web framework for building APIs — built on Starlette (ASGI) and Pydantic. It delivers automatic validation, serialization, and interactive docs with minimal code. Benchmarks show it rivals Node.js and Go in raw throughput.

Language
Python 3.8+
Built on
Starlette + Pydantic
Server
Uvicorn (ASGI)
Created
Sebastián Ramírez

The three pillars of FastAPI

⚡ Speed — truly async
ASGI-based, every endpoint can be async. The server handles thousands of concurrent requests without blocking. Benchmarks: comparable to Node.js and Go at I/O-heavy workloads, far ahead of Flask/Django in concurrency.
🧠 Type hints = everything
Python type annotations drive validation, serialization, OpenAPI docs, and editor autocomplete. Write a typed function — FastAPI generates the entire API contract. No separate schema files, no marshmallow decorators, no manual validation code.
📖 Zero-effort OpenAPI docs
Swagger UI at /docs and ReDoc at /redoc are generated automatically from your code. Every route, parameter, schema, and error response is documented without writing a single line of doc code. This alone saves hours per sprint versus Flask/DRF projects.

What FastAPI is NOT

Not batteries-included. FastAPI has no built-in ORM, admin panel, authentication system, email sending, templating engine, or migration tool. This is intentional — you compose your own stack. It's a strength for API-only backends and a gap when you need Django's full ecosystem.
Why we pair with Django (minimum). Django provides the admin panel at /admin, the User model, built-in auth, ORM with migrations, and management commands. FastAPI provides the high-performance JSON API. They share the same PostgreSQL database and complement each other perfectly. You get the best of both worlds.

Module 2 · Introduction

Why FastAPI?

Understanding the design decisions, killer features, and trade-offs that make FastAPI the right choice for modern Python API development.

The problems with older Python frameworks

Flask — micro but too manual
Zero built-in validation, serialization, or docs. Every project adds marshmallow/voluptuous/pydantic manually. WSGI-based = one request per thread. Adding async is a patch job. Great for learning, limiting at scale.
Django REST Framework — powerful but heavy
Verbose serializers, complex class-based views, synchronous-first architecture. The ORM is sync, WSGI-based, and adding proper async requires significant refactoring. Admin and auth are excellent; the API layer is showing its age.

FastAPI's killer advantages

1
Type hints replace schema files entirely
In Flask/DRF you write a schema class separately, then connect it to a route manually. In FastAPI, the function signature IS the schema. Parameters with type annotations are automatically validated, serialized, and documented. No marshmallow, no extra files, no glue code.
2
Async-first without plugins
Write async def for I/O-bound work. FastAPI runs it on the event loop. Write plain def for CPU-bound work. FastAPI runs it in a thread pool. Both are correct. No special plugin, no framework switch, no trade-off.
3
Dependency injection built into the framework
The Depends() system lets you inject database sessions, auth checks, pagination, config, and feature flags into any route — with automatic cleanup after the request. This makes testing trivial: override any dependency with a mock in one line.
4
Swagger UI generated automatically
Visit /docs — every route, parameter, request body, and response schema is there, interactive, with working "Try it out" buttons. Frontend developers can test the API without Postman. This saves 2–4 hours per sprint on communication and manual testing.
5
Outstanding editor support
Because everything is typed, VS Code and PyCharm give you autocomplete inside route handlers, Pydantic models, and DI-injected parameters. You catch bugs at write-time. Refactoring is safe — rename a model field and TypeScript-style errors appear everywhere it's used incorrectly.
Industry adoption: FastAPI has 75,000+ GitHub stars (more than Flask). Used in production at Microsoft, Netflix, Uber, Lyft, and hundreds of startups. The community is the fastest-growing in the Python web framework space as of 2024–2025.

Path & Query Parameters

Three ways to receive data in GET requests — path params (in the URL), query params (after ?), and how to validate, constrain, and document them.

Path parameters

Declared in the route string with {name} and typed in the function signature. Always required. FastAPI validates the type automatically — passing the wrong type returns 422.

path parameters with validation
from fastapi import APIRouter, Path, HTTPException from enum import Enum router = APIRouter() # Basic — type validated automatically @router.get("/items/{item_id}") async def get_item(item_id: int): return {"item_id": item_id} # GET /items/42 → {"item_id": 42} # GET /items/abc → 422 Unprocessable Entity # Path() — adds constraints + docs metadata @router.get("/users/{user_id}") async def get_user( user_id: int = Path( ..., # ... = required (no default) title="User ID", description="Must be a positive integer", gt=0, # greater than 0 le=1_000_000 # less than or equal ) ): return {"user_id": user_id} # Enum — restricts to specific string values class StatusEnum(str, Enum): active = "active" inactive = "inactive" banned = "banned" @router.get("/users/status/{status}") async def get_by_status(status: StatusEnum): return {"status": status, "value": status.value} # GET /users/status/active → OK # GET /users/status/deleted → 422 (not in enum)

Query parameters

Any function parameter that is NOT in the path string is treated as a query parameter. Optional ones use Optional[type] = None or just type = default.

query parameters
from fastapi import Query from typing import Optional, List @router.get("/items/") async def list_items( skip: int = 0, # optional, default 0 limit: int = 10, # optional, default 10 search: Optional[str] = None, # truly optional — no default is_active: bool = True, # ?is_active=false works ): return {"skip": skip, "limit": limit, "search": search} # GET /items/?skip=20&limit=5&search=laptop&is_active=true # Query() — add validation + docs @router.get("/products/") async def list_products( q: Optional[str] = Query( default=None, min_length=2, max_length=50, description="Search query string" ), tags: List[str] = Query(default=[]), # multi-value: ?tags=a&tags=b price_min: float = Query(default=0, ge=0), price_max: float = Query(default=9999, le=100000), ): return {"q": q, "tags": tags, "price_range": [price_min, price_max]} # GET /products/?q=phone&tags=electronics&tags=sale&price_min=100

Response Models

Controlling exactly what data you return — filtering sensitive fields, defining response schemas, and handling multiple response types per endpoint.

Why response_model matters

Never return your ORM model directly. Your DB model has fields like password_hash, internal_notes, deleted_at. Without a response_model, these leak into the API response. response_model= acts as a strict output filter — only defined fields pass through.
response_model filtering
# DB model has sensitive fields class UserDB(BaseModel): id: int; username: str; email: str password_hash: str # ← NEVER expose is_admin: bool # ← maybe don't expose # Safe public response class UserResponse(BaseModel): id: int; username: str; email: str @router.get("/users/{id}", response_model=UserResponse) async def get_user(id: int): user = await fetch_user(id) # returns UserDB return user # FastAPI strips password_hash, is_admin # Modifier flags @router.get("/me", response_model=UserResponse, response_model_exclude_none=True, # skip None fields response_model_exclude_unset=True, # skip unset fields response_model_exclude={"email"}, # always exclude specific fields ) async def get_me(): ...

File Uploads

Handling single and multiple file uploads, validating file types and sizes, and integrating with cloud storage.

Requires: pip install python-multipart. FastAPI raises an error if this package is missing when you use File() parameters.
file upload endpoint
from fastapi import File, UploadFile, HTTPException import shutil, uuid from pathlib import Path UPLOAD_DIR = Path("uploads") UPLOAD_DIR.mkdir(exist_ok=True) ALLOWED_TYPES = {"image/jpeg", "image/png", "image/gif", "application/pdf"} MAX_SIZE_MB = 10 @router.post("/upload/") async def upload_file(file: UploadFile = File(...)): # 1. Validate content type if file.content_type not in ALLOWED_TYPES: raise HTTPException(400, f"File type {file.content_type} not allowed") # 2. Read file content into memory to check size contents = await file.read() size_mb = len(contents) / (1024 * 1024) if size_mb > MAX_SIZE_MB: raise HTTPException(413, f"File too large: {size_mb:.1f}MB (max {MAX_SIZE_MB}MB)") # 3. Generate unique filename (never trust client filename) ext = Path(file.filename).suffix unique_name = f"{uuid.uuid4()}{ext}" file_path = UPLOAD_DIR / unique_name # 4. Save to disk with open(file_path, "wb") as f: f.write(contents) return { "original_name": file.filename, "saved_as": unique_name, "size_kb": round(size_mb * 1024, 2), "content_type": file.content_type, } # Multiple files + form fields combined @router.post("/upload-multi/") async def upload_multi( title: str = Form(...), files: list[UploadFile] = File(...), ): saved = [] for file in files: contents = await file.read() name = f"{uuid.uuid4()}{Path(file.filename).suffix}" (UPLOAD_DIR / name).write_bytes(contents) saved.append(name) return {"title": title, "saved_files": saved}

✓ Best practices

  • Validate MIME type AND extension
  • Generate UUID filenames — never trust client names
  • Store uploads in S3/GCS in production
  • Stream large files — don't load into RAM
  • Limit upload size at Nginx level too

✗ Avoid

  • Don't store files inside your app directory
  • Don't trust client-provided filenames
  • Don't skip virus scanning in security-sensitive apps
  • Don't load very large files into memory
  • Don't serve uploaded files without CDN in prod

The Depends() System

FastAPI's dependency injection — the most powerful feature for writing clean, reusable, testable code. Understanding Depends() separates beginner code from professional FastAPI architecture.

What is dependency injection?

Simple definition: A dependency is just a function whose return value is automatically passed into your route handler by FastAPI. This is great for: database sessions (auto-opened and closed), auth checks, pagination params, feature flags, rate limiting, and config injection.

Async / Await in Python

Python's async model, the event loop, coroutines, and how FastAPI leverages async to handle thousands of concurrent connections. Understanding this is the key to writing truly performant FastAPI code.

The mental model — cooperative multitasking

Async ≠ parallel. Python is single-threaded. Async means: while waiting for I/O (DB query, HTTP call, file read), surrender the event loop so other tasks run. When I/O finishes, resume. No OS threads, no GIL fights — just one thread cooperating with itself.

Common mistake: calling a blocking sync operation inside async def. Using requests.get() or time.sleep() inside an async route BLOCKS the event loop and freezes ALL concurrent requests. Use httpx.AsyncClient and asyncio.sleep().

✓ REST naming rules

  • Use nouns, not verbs (/users not /getUsers)
  • Plural resource names (/users not /user)
  • Use hyphens for multi-word (/blog-posts)
  • All lowercase URLs
  • Version in URL: /api/v1/...
  • Nest for ownership: /users/42/orders

✗ Common mistakes

  • Verbs in URL: /api/createUser
  • Inconsistent casing: /Users/GetById
  • Deep nesting: /orgs/1/teams/2/users/3/posts
  • No versioning: /api/users (no v1)
  • HTTP method misuse: DELETE data with GET
  • Always 200 OK even for errors

Consistent error response format

Troubleshooting Guide

Common problems in FastAPI + Django development and exactly how to fix them — validation errors, database issues, auth failures, CORS problems, and async pitfalls.

422 Unprocessable Entity on every request +
This is a Pydantic validation failure. The request body, path params, or query params don't match your schema.

Step 1: Read the full error response — it tells you exactly which field failed and why: {"detail": [{"loc": ["body", "email"], "msg": "value is not a valid email", "type": "value_error.email"}]}

Step 2: Check your Pydantic model — did you use EmailStr? Is the field required (no default) but you're not sending it?

Step 3: Check Content-Type header — JSON body requires Content-Type: application/json. Form data requires application/x-www-form-urlencoded.
CORS errors in browser (Access-Control-Allow-Origin) +
The browser is blocking the request because the API doesn't include CORS headers.

Fix 1: Make sure CORSMiddleware is added BEFORE all other middleware and routers:
app.add_middleware(CORSMiddleware, allow_origins=["http://localhost:3000"], allow_credentials=True, allow_methods=["*"], allow_headers=["*"])

Fix 2: If using allow_credentials=True, you CANNOT use allow_origins=["*"]. You must list specific origins.

Fix 3: The preflight OPTIONS request must also be allowed. FastAPI handles this automatically with CORSMiddleware.

Fix 4: Check that your Nginx config isn't stripping CORS headers — add proxy_pass_header Access-Control-Allow-Origin; if needed.
SQLAlchemy "greenlet_spawn has not been called" or async errors +
You're calling async SQLAlchemy operations from a sync context, or vice versa.

Fix 1: Make sure your route is async def if you're doing await db.execute().

Fix 2: Set expire_on_commit=False in your async_sessionmaker. This prevents lazy-loading errors when you access ORM attributes after the session closes.

Fix 3: Use await db.refresh(obj) after committing if you need to read updated fields.

Fix 4: Don't access lazy-loaded relationships outside the session. Use selectinload() or joinedload() to eagerly load them.
JWT token: "Could not validate credentials" on every protected route +
Token validation is failing. Work through these checks:

Check 1: Is the Authorization header correct? It must be exactly: Authorization: Bearer eyJhbGci... (capital B, space after Bearer).

Check 2: Is the JWT secret key the same on generation and validation? A common mistake is having two different JWT_SECRET_KEY values in dev and prod env vars.

Check 3: Is the token expired? JWT has "exp" claim — if expired, you get 401. Implement token refresh.

Check 4: Decode the token manually at jwt.io and check the payload. Make sure sub (user_id) is a string, not an int — jwt.decode() needs consistent types.
Django admin 500 errors / static files not loading +
Most Django admin issues in production are static files or settings problems.

Fix 1: Run python manage.py collectstatic to gather admin CSS/JS into STATIC_ROOT.

Fix 2: Set STATIC_ROOT in settings and configure Nginx to serve /static/ from that directory.

Fix 3: Set ALLOWED_HOSTS = ["yourdomain.com"] in Django settings for production.

Fix 4: Set DEBUG = False in production and set SECRET_KEY from environment variable.

Fix 5: Check python manage.py check --deploy — Django will list all security issues.
Async endpoint is slow / blocking other requests +
Something is blocking the event loop. Classic causes:

Issue 1: Using requests library instead of httpx.AsyncClient inside an async route.

Issue 2: Using synchronous SQLAlchemy (session.query()) instead of async (await session.execute()).

Issue 3: CPU-heavy computation in async def — move it to a def function and use run_in_threadpool().

Issue 4: time.sleep() instead of await asyncio.sleep().

Detect it: Install pip install asyncio-monitor or log request timing with middleware to identify slow endpoints.
Pydantic v1 vs v2 migration errors +
FastAPI 0.100+ uses Pydantic v2. Many v1 patterns are removed.

orm_mode = True → replace with model_config = ConfigDict(from_attributes=True)

.dict() → replace with .model_dump()

.parse_obj() → replace with .model_validate()

@validator → replace with @field_validator (class method now required)

class Config: → replace with model_config = ConfigDict(...)

Auto-fix tool: pip install bump-pydantic && bump-pydantic . — migrates your codebase automatically.
Alembic autogenerate doesn't detect my model changes +
Alembic's autogenerate only works if it can see your models.

Fix 1: In alembic/env.py, import ALL your models before setting target_metadata. Even if they're not directly used, they must be imported so SQLAlchemy registers them in the metadata.

Fix 2: Make sure target_metadata = Base.metadata — not None.

Fix 3: For type changes, add compare_type=True to the context.configure() call.

Fix 4: Alembic can't autogenerate: CHECK constraints, partial indexes, custom types, or table renames. Add these manually to the migration file.
